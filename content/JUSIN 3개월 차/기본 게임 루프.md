Win32API의 GetMessage 함수는 메세지가 있을 때만 실행되기 때문에 게임루프와는 어울리지 않음.

----
### GetMessage vs PeekMessage
- Get은 메세지가 없으면 block, Peek은 메세지가 없으면 false반환
- 메세지가 없어도 계속 루프가 돌아야 하는 게임 특성상 PeekMessage를 사용해야 함

### 화면 갱신
- 그냥 Update, Render를 반복할 경우 루프를 도는 속도가 너무 빨라서 제어할 수 없음
- InvalidateRect()을 통한 화면 갱신은 사용하지 않는다
- GetTickTime()을 통한 의도적인 프레임 제한을 통해 Update, Render의 주기를 정해준다

```cpp
DWORD dwTime = GetTickTime();

while (true)
{
    // PM_REMOVE : 메세지 큐에 있는 메세지를 확인 후 제거
    // PM_NOREMOVE : 메세지 큐에 메세지 여부만 확인, 만약 메세지를 가져와야 할 경우, 개별적으로 getmessage 함수를 호출해야 함

    if (PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE))
    {
        if (WM_QUIT == msg.message)
            break;

        if (!TranslateAccelerator(msg.hwnd, hAccelTable, &msg))
        {
            TranslateMessage(&msg);
            DispatchMessage(&msg);
        }
    }
    
    else
    {
        if (dwTime + 10 < GetTickCount())
        {
            MainGame.Update();
            MainGame.Render();

            dwTime = GetTickCount();
        }        
    }
    
}
```

### 오브젝트 이동
- Update()에서 오브젝트의 위치 이동, 속도, 상태 변화 등 논리적인 움직임을 갱신한다.
- Update_Rect()는 Update()에서 갱신한 정보를 바탕으로 화면에 출력할 Rect를 계산한다
```cpp
class CObj
{
protected:
	INFO	m_tInfo;
	RECT	m_tRect;
	float	m_fSpeed;
	void Update_Rect();
public:
	CObj();
	virtual~CObj(){}

	virtual void Initialize()PURE;
	virtual void Update()PURE;
	virtual void Render(HDC hdc)PURE;
	virtual void Release()PURE;
};
```
### 플레이어 Update()예시
```cpp
void CObj::Update_Rect()
{
	m_tRect.left	= LONG(m_tInfo.fX - (m_tInfo.fCX * 0.5f));
	m_tRect.top		= LONG(m_tInfo.fY - (m_tInfo.fCY * 0.5f));
	m_tRect.right	= LONG(m_tInfo.fX + (m_tInfo.fCX * 0.5f));
	m_tRect.bottom	= LONG(m_tInfo.fY + (m_tInfo.fCY * 0.5f));
}
//위치, 크기를 바탕으로 화면에 출력할 rect 계산
void CPlayer::Update()
{
	CObj::Update_Rect();
	Key_Input();
}
//키 입력에 따른 움직임을 계산하고 Update_Rect 호출출
```

### 오브젝트의 위치 표현
- fX, fY는 현재 오브젝트의 중심 위치, fCX, fCY는 오브젝트의 가로 세로 크기를 의미한다
- DX에서는 이런 식으로 표현 한다고 함(WinAPI에서는 연습)
```cpp
typedef struct tagInfo
{
	float fX;
	float fY;

	float fCX;
	float fCY;
}INFO;
```
